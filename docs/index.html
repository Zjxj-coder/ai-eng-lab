真实事故复盘 3 则

三次真实故障的根因追溯：现象、我最初的错误假设、真因，以及每一次之后判据怎么改

systemdnetifdBashcgroup

以下三则是系统在长期运行中发生的真实阻断级故障。相较于简单的进程重启恢复，我更注重通过四步分析法挖掘深层根因，彻底消灭同类时序与状态问题，使系统架构愈发健壮。

  • 路由遮蔽：【现象】全域断网两天【错误假设】 ISP 阻断【真因】 100.64/10 路由遮蔽 CGNAT 网关，致 netifd 装默认路由失败且不重试【判据修正】增加强制网关重试与常驻网络守护脚本。
  • 自举死锁：【现象】守护脚本无响应卡死【错误假设】内存溢出【真因】 systemd 启动事务内 restart 自身产生永久状态死锁【判据修正】引入 cgroup 自省闸门，禁止递归式的自身服务重启。
  • 更新失灵：【现象】 OpenClash 内核久未更新【错误假设】远端服务器宕机【真因】厂商脚本强依赖 clash_version.sh 刷新的缓存文件，不调则永判无变化【判据修正】改写逻辑对比二进制哈希。

go// 路由熔断降级核心
func (r *Router) ExecuteTask(ctx context.Context, task *Task) (*Result, error) {
    var lastErr error
    for _, provider := range r.Providers {
        if r.CircuitBreaker(provider.ID).Allow() {
            res, err := provider.Generate(ctx, task)
            if err == nil && r.ValidateOutput(res) {
                return res, nil
            }
            r.CircuitBreaker(provider.ID).RecordFailure()
            lastErr = err
        }
    }
    return nil, fmt.Errorf("providers exhaust: %w", lastErr)
}

从设计到落地：三个项目的验收记录

三份设计稿走到可复跑的实际过程，以及每一轮被打回的真实原因

产出级验收独立复跑不变量断言

三个项目由 Antigravity 的 gemini-3.1-pro-high 接单实现，由我逐轮验收。验收不看它的完成报告，而是在本机重跑 vet、测试、race 与 bench —— 因为如果只看报告，第一轮就"全部通过"了。Relay 打回 1 次、Sibyl 打回 1 次、Nexus 打回 8 次，全部收敛后才入库。

  • Relay：第一版把目标 p99 倒推成时钟步进（clk.advance(360ms) // 360*5=1800），单点值冒充分位数。改成 200 次带种子试验后取真分位，值从 1800ms 变成 2801ms —— 数字变了，恰恰证明它原先是假的。
  • Sibyl：混合检索相对纯 BM25 零提升。根因是重排 bonus 量级 1~3，把 RRF 的 0.016 淹没了两个数量级，融合退化成 BM25 的同义重排。改成三路排名同量纲进 RRF 后，召回 0.71 → 0.95。
  • Nexus：命中率 0.734 高于语料 44% 的冗余上限 —— 数学上只能是语义缓存误命中，在真实系统里等于把上个请求的答案返给了下一个。加 false_hit_rate 指标并收紧阈值后降到 0.445。

同一个教训出现了三次：我写「误命中率 ≤ 0.01」，它把语义缓存关死；我写「断言 overhead > 0」，它加了个下限夹板；我写「p99 ≈ 1.8s」，它倒推参数。只约束一侧的判据总能被退化解满足，而退化解往往看起来很合理。可行的写法是标定式——注入已知量，断言测得值接近它；以及断言不变量——min ≤ p50 ≤ mean ≤ p99 ≤ max、去重+拒绝+处理 = 提交。数字会漂，不变量不会。

工程判据方法论

本作品集的全部陈述与代码始终遵循可复现、重客观的工程价值观底色。技术探索永远不能停留在 Demo 跑通阶段，而是必须深究如何在分布式的、高并发量冲击下乃至环境极度受限时，捍卫系统一致性与可用性的正确状态。

  • 杜绝弱势判据：永远不单纯以某个守护进程的 running 状态当作网络健康的衡量，坚决抵制将系统命令的返回码当成最终链路操作确实生效的免死金牌。
  • 强调隔离兜底：无论是涉及地域隔离的异地网络拓扑，还是调用多套云端第三方大模型 API 的中枢调度，均需强制预留真正独立的物理隔离带与不打折扣的降级管线。
  • 推崇实证反演：所有的系统响应性能基线宣称全部依靠剥离敏感业务信息的离线日志展开极限压力回放，大模型的智能程度与代码水平严格经由多维离线基准测试集予以剥离量化。
