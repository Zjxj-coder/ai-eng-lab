## 贯穿全仓库的一条原则：弱判据 vs 强判据

这不是口号，是踩出来的。它同时决定了这几个仓库怎么写测试。

| 弱判据（不用） | 为什么不可信 |
|---|---|
| 进程退出码 `0` | 实测供应商限流时进程仍 `exit 0` |
| “有输出” | **错误信息也是输出** |
| “服务 active” | 服务活着不等于功能生效 |
| 在路由器本机 `curl` 通了 | 本机流量不经 PREROUTING，不等价于 LAN 客户端 |

| 强判据（实际用的） | 怎么落地 |
|---|---|
| 结构化 usage 字段 | `completed && !failed && api_calls >= 1` |
| 产出文件真的存在 | 存在 + **非 0 字节** + **mtime 晚于派单时刻** |
| 端到端合成客户端 | netns + veth 造一个真 LAN 客户端去自证 |
| 补丁不得改动测试文件 | 防止 Agent 靠删断言让测试变绿 |
